# 学校バス運行管理 Go版

Goの処理側と、HTML、CSS、JavaScriptの管理画面で構成した運行管理です。外部ライブラリは使っていません。

## 主な機能

1. 現在の18表入りExcelを直接取込
2. 日付と曜日ごとに運行便を自動作成
3. 乗車人数、車両番号、担当者、連絡事項を保存
4. 乗車受付、出発、到着、運休、待機への戻し
5. 実績時刻と遅延分数を自動計算
6. 操作履歴を最大2000件保存
7. 同時更新時の競合をGo側で制御
8. 定員到達と定員超過を色、文章、音声で警告
9. 出発3分前と1分前を日本語音声で通知
10. 運用単位で担当者、車両、定員を固定
11. 通信断中の変更を端末内へ一時保存し、復帰後に自動同期
12. GPS現在地、測位精度、停留所単位の経路進捗を集中表示
13. OpenStreetMap上で往路と復路の道路経路を作成
14. 路線、方向、時間帯、車両条件により各便へ経路を自動割当
15. 各便の往路経路と復路経路を個別変更
16. 往路と復路の受付、人数、出発、到着、経路進捗を個別管理
17. 元ダイヤを画面上で編集し、通常便、回送、団体専用、運行なしを往復別に設定
18. 起動直後に管理画面または運用1から9を直接選択
19. 全車両の最新GPS位置を一枚の地図へ表示
20. 学校を共通地点⓪として登録し、校内測位を同地点へ補正
21. 携帯画面では主要5項目を画面下へ固定し、片手操作へ最適化
22. 装飾を整理し、重要状態と確定操作を色で判別できる簡潔な表示
23. 管理者、運転担当、閲覧担当の権限別ログイン
24. 不正な状態遷移を処理側で拒否し、同時更新の競合を同期画面で確認
25. PWA対応により、通信断後の再読込でも基本画面を起動
26. GPSの更新遅延、低精度、異常な位置飛びを判定して表示
27. 10名追加は通知内から取り消し可能
28. 元ダイヤの時刻順、重複、未入力を保存前に検査
29. 一般用のご案内をログインなしで公開し、希望の時刻から便を選び出す
30. 学校発と学校着しかないダイヤから、駅ごとの発車時刻と到着時刻を自動計算
31. 乗り場の場所と目印を登録し、地図アプリへ直接案内
32. 行きと帰りで別々の駅を選択
33. 帰りの最終便を常に併記
34. 管理設定、来場者の検索、前回の乗車実績から混雑を予測
35. 東武東上線、JR川越線、西武新宿線の運行情報を最上部へ表示
36. 当日のお知らせを管理画面からその場で掲示
37. ダイヤ管理画面から便の追加、変更、削除、曜日間の複製を実施
38. ステージ進行を登録し、開始に間に合う便と終了後の便を自動案内

## 画面構成

URLに記号を付けず、同じ処理側で公開します。

| URL | 画面 | 必要な権限 |
| --- | --- | --- |
| `/` | 一般用のご案内 | 不要 |
| `/guide` | 案内設定（乗り場、所要時間、お知らせ、混雑予測、沿線情報） | 不要 |
| `/diagram` | ダイヤ管理 | 管理者 |
| `/program` | ステージプログラム管理 | 管理者 |
| `/staff` | 当日運行、全車両位置、経路管理、操作履歴 | 職員 |

`/staff.html` などの旧URLは、対応する新URLへ転送します。

## 一般用のご案内

`/` はログインなしで開けます。運用番号、便番号、担当者、車両番号、乗車人数、GPS位置は表示しません。

来場者が知りたいのは「何時に学校へ着きたいか」「何時ごろ帰りたいか」です。画面は時刻表ではなく、そこから便を選ぶ作りにしています。1画面のまま、選んだ項目がその場で下に開きます。

画面の上から順に、沿線の運行情報、当日のお知らせ、開催日の切替、次の5つの入口が並びます。

1. 学校へ行く 駅と「学校に着きたい時刻」を選ぶと、その時刻までに着く便を選び出します
2. 学校から帰る 駅と「学校を出発したい時刻」を選ぶと、その時刻以降の便と最終便を出します
3. 時刻表をすべて見る その日の全便を、駅の発車時刻の一覧で表示します
4. 乗り場をさがす 駅ごとの乗り場、目印、徒歩の分数、地図アプリへのボタン
5. 催しに合わせて調べる 見たい催しを選ぶと、開始に間に合う便と終了後に出る便を出します

行きと帰りで駅が違う場合にも対応します。行きの駅を選ぶと帰りの駅も同じ駅を初期値にしますが、別の駅へ選び直せます。

結果には、駅の発車時刻、学校の到着時刻、所要時間の目安、乗り場の場所と目印、地図ボタン、混雑予測、この次の便を表示します。希望の時刻と30分以上離れる場合は、その旨と待ち時間を明示します。選んだ駅の路線に遅れが出ているときは、結果の中にも表示します。

運休は候補から外し、時刻表の一覧にだけ「運休」と表示します。回送と団体専用の区間は表示しません。

表示内容は公開API `GET /api/public/guide?day=土曜&date=2026-10-03` から一度に取得します。日付を省略すると当日の運行状況は付きません。

### 駅の発車時刻の計算

元のダイヤには学校発と学校着しか入っていません。駅での時刻は、案内設定に登録した区間の所要時間から計算します。

```
区間 学校↔ふじみ野 15分、学校↔南古谷 10分、学校↔本川越 25分、南古谷↔本川越 20分

学校 8:20発 → 本川越 8:45着 → 本川越 8:55発 → 学校 9:20着
（走行25分を足して到着、残りの時間を駅での停車として配分）
```

複数の駅を回る便も、区間を順に足して各駅の時刻を出します。停車時間が計算できない片道便は5分として扱います。1つの便が同じ駅に2回停まる場合、帰りの便はいちばん早く着く停車、行きの便はいちばん遅く出る停車を採用します。

経路に「経由」とは表示せず、駅ごとの発車時刻と到着時刻としてご案内します。

### 導入と図像

`/` を初めて開くと、15秒の導入が流れます。城北埼玉 けやき祭 → テーマ「Go Beyond」→ けやき祭実行委員会 委員長のお言葉、の3幕です。

導入は1セッションに1回だけです。画面のどこかに触れる、キーを押す、「とばす」を押す、のいずれでも中断できます。端末の「視差効果を減らす」設定が入っている場合は再生しません。時刻を調べに来た方を待たせないためです。

委員長のお言葉は `web/public.js` の `CHAIR_WORD` に入れてください。空のままだと、公開前に気づけるよう赤枠の仮置きが出ます。

跳ぶ生徒の図像は `web/assets/brand/student-leap.webp` です。差し替える場合は、背景が透過したWebPを同じ名前で置いてください。

### 混雑予測### 混雑予測

3つの材料を使い、優先度の高いものを表示します。

1. 案内設定で登録した時間帯（最優先）
2. 来場者が調べた希望時刻の集中。15分単位の件数だけを匿名で数えます。個人を識別する情報、IP、Cookieは保存しません
3. 直近の運行日の乗車実績。定員に対する割合が7割で「混み合う」、9割で「大変混み合う」

人数や「満席」は表示しません。

### 催しに合わせたご案内

「催しに合わせて調べる」では、登録したステージ進行ごとに次を自動計算します。

1. 行き 開始時刻までに学校へ着く便のうち、いちばん遅い便
2. 帰り 終了時刻の後に学校を出る、いちばん早い便

行きと帰りで別々の駅を選べます。運休の便は候補から外します。

## 案内設定

`/guide` はログインなしで開けます。当日その場で直せるようにするためです。`GUIDE_LOCK=1` を設定すると管理者のログインが必要になります。

| タブ | 登録するもの | 一般用での表示 |
| --- | --- | --- |
| 開催日 | 行事名、土曜ダイヤの日、日曜ダイヤの日 | 画面上部の日付と切替 |
| 乗り場 | 駅名、路線、乗り場の名前、目印、徒歩の分数、緯度経度 | 乗り場の案内と地図ボタン |
| 所要時間 | 区間ごとの片道の所要時間 | 駅の発車時刻と到着時刻の計算 |
| お知らせ | 出す日、目立たせ方、見出し、本文 | 画面上部の帯 |
| 混雑予測 | 曜日、向き、駅、時間帯、程度 | 結果の中の混雑表示 |
| 沿線情報 | 路線ごとの状態と本文 | 画面最上部の運行情報 |

所要時間のタブでは、登録した値が全便のダイヤに収まるかを自動で確かめます。区間が未登録の場合や、走行時間が運行時間を超える場合はその便を一覧で示します。

乗り場に緯度経度を登録すると、一般用に地図ボタンが出ます。iPhoneとiPadではAppleマップ、それ以外ではGoogleマップが開きます。

## 沿線の運行情報

東武東上線、JR川越線、西武新宿線の運行情報を画面最上部に表示します。乗り降りする駅の路線に遅れが出ている場合は、便の案内の中にも表示します。

取得先はHUBBの `traininfo-api`（JR東日本公式ページ、公共交通オープンデータセンター、関東私鉄各社公式を統合した独立GAS。5分更新、匿名GET、個人情報なし）です。処理側が5分ごとに取得します。アクセストークンの設定は不要です。

```
# 取得先を変える場合だけ指定します
TRAININFO_API=https://example/exec go run .
```

対応する路線IDは `tobu.tojo`、`jreast.kawagoeline`、`seibu.shinjuku` です。状態は平常運転、遅延、運転見合わせ、お知らせ、情報なしの5つに正規化します。

取得できないときは、案内設定の「沿線情報」タブで手入力した内容を表示します。手入力の内容は、次の自動取得まで残ります。

運行情報の出典表示は一般用画面の最下部へ自動で出します。これは提供元の利用条件です。

## 画面操作

1. 画面上部で運行日と土曜、日曜を選択
2. 最優先の便を上段へ表示し、乗車受付、出発、到着を順に記録
3. 便一覧では、1名減少、1名追加、10名追加、直接入力をその場で保存
4. 出発、到着、運休は対象便を確認してから確定
5. 5分以上の遅延、連絡事項、運休を色と枠で強調
6. 狭い画面では表を便単位の縦表示へ切替
7. 集中表示では、担当運用を選び、全便を左右に動かして確認

## 携帯画面

画面幅900px以下では、管理項目を画面下へ固定します。当日運行、元ダイヤ編集、全車両位置、経路管理、操作履歴を親指で切り替えられます。

画面幅640px以下では、日付を上段、再読込と集中表示を下段へ配置します。運行便は縦表示となり、人数変更、便情報、次操作を48px以上の操作領域で表示します。入力欄は16px以上とし、携帯端末で意図しない画面拡大が起きにくい構成です。

集中表示では、往路と復路、便の切替、人数、確定操作の順に並びます。確定操作は画面下に追従しますが、一覧内容を隠さない範囲で移動します。横向きでは追従を解除し、表示高さを確保します。

## 集中表示

当日運行の上部にある「集中表示」から起動すると、最初に今日の担当運用を選択します。選択内容は運行日と曜日ごとに端末へ保存され、次回は前回選択として強調表示されます。各便の「集中」から起動した場合は、その便の運用を直接開きます。

1. 運用番号、担当者、車両、運行時間、残り便数から担当運用を選択
2. 選択運用の全便を時刻順に横表示
3. 左右操作または前後ボタンで過去便、現在便、今後の便を確認
4. 待機または乗車受付中は、出発までの残り時間を補助情報として表示
5. 運行中は、予定到着までの残り時間へ自動切替
6. 到着記録後は同じ運用の次便へ自動移動
7. 乗車人数を1名減少、1名追加、10名追加で入力
8. 現在便の経路、車両、担当、注意事項を表示
9. 通信状態と現在時刻を常時表示
10. 対応端末では画面消灯を防止
11. 運用設定から担当者、車両、定員、音声通知、GPSを設定
12. 定員到達時は橙色、超過時は赤色で警告
13. 通信断中は未送信件数を表示し、復帰後に保存順で同期
14. GPS座標と測位精度を表示し、停留所の進捗は前後ボタンで記録
15. 往路と復路を上部で切り替え、選択中の片道だけを操作
16. 回送区間では乗車受付を表示せず、回送出発から記録
17. 団体専用便は便種別を明示して通常便と区別

出発と到着は、対象便を確認してから確定します。操作は必ず停車中に行ってください。

画面消灯防止は、HTTPS接続またはlocalhostで利用できます。端末やブラウザが未対応の場合でも、集中表示の他機能はそのまま利用できます。

音声通知は集中表示を開いている間に、出発予定の3分以内と1分以内で各1回実行します。端末側の音量、消音設定、ブラウザの音声対応に左右されるため、運用設定の「音声をテスト」で事前確認してください。

担当者、車両、定員の固定設定は、選択中の運用に属する未完了便へまとめて反映されます。到着済みと運休済みの便は変更しません。初期定員は55名です。

通信断中の人数、出発、到着、経路進捗、運用設定、GPS位置はブラウザのlocalStorageへ一時保存します。通信復帰後は自動送信し、操作時刻と識別番号を使って同じ操作の重複登録を防ぎます。ブラウザのデータ消去や端末交換を行う前に、保留件数が0件であることを確認してください。

GPSはHTTPS接続またはlocalhostで利用できます。許可後は約20秒ごと、または約25m以上移動した時に位置を送信します。集中表示を閉じると測位を停止します。停留所ごとの判定半径をまだ設定していないため、GPSだけで停留所通過を自動判定せず、経路進捗は運転者または添乗者が停車中に記録します。

学校地点⓪の補正半径内では約10秒ごとに位置を更新し、地図上の表示位置を学校地点⓪へ統一します。表示には端末が返した実測精度も併記します。一般的な携帯端末のGPSだけで誤差1mを保証できないため、1m以内は目標精度として表示し、精度が低い測位を隠しません。

## ダイヤ管理

ダイヤが変更になった場合は `/diagram` で修正します。管理者権限が必要です。保存した内容は一般用の時刻案内と当日運行へそのまま反映されます。

1. 一周の出発、帰着、全体経路を編集
2. 往路と復路の出発、到着予定を別々に編集
3. 往路と復路ごとに通常便、回送、団体専用、運行なしを設定
4. 団体名、回送理由、乗車条件などを詳細情報へ保存
5. 便の追加と削除、もう一方の曜日への複製
6. Excelからの一括取込
7. 一般用での見え方を保存前に確認

画面上部の「保存前の確認事項」では、同一出発時刻の重複、運用内の時間重複、帰着が出発より前の便、駅着と駅発が未入力の便を一覧にします。行の「この便を開く」から対象の便へ移動できます。

便を削除すると、人数も実績も記録されていない運行だけを同時に削除します。実績がある運行と運休済みの運行は残ります。

既存Excelに中間時刻がない便は、往路出発と復路到着だけを自動継承します。駅到着時刻と駅出発時刻はこの画面から補完してください。補完するまで、一般用では往路が学校発だけ、復路が学校着だけの表示になります。

職員用画面の「元ダイヤ編集」からも同じ内容を編集できます。

## ステージプログラム管理

文化祭などのステージ進行は `/program` で登録します。管理者権限が必要です。

1. 曜日、会場、開始、終了、内容、詳細を登録
2. もう一方の曜日へ複製
3. 一般用での「間に合うバス」を保存前に確認
4. 開始時刻までに学校へ着く便がない進行は件数で警告

`data/store.json` には土曜のステージプログラムを登録済みです。すでに稼働中の保存先へは初期ダイヤの複製が行われないため、その場合はこの画面から登録してください。日曜分は届き次第この画面から追加できます。

## 全車両位置

管理項目の「全車両位置」では、運用1から9の最新位置を15秒ごとに再読込します。位置が未送信の車両は一覧で明示します。学校地点⓪は管理端末の現在地から登録でき、補正半径は5mから200mで設定できます。

## 経路管理

管理項目の「経路管理」から道路経路を作成します。

1. 経路名、路線、往路または復路を設定
2. 必要に応じて開始時刻、終了時刻、車両番号を設定
3. 地図上で出発地点、経由地点、到着地点を順に追加
4. 「道路に沿って作成」で道路経路、距離、所要時間を取得
5. 経路を保存
6. 「条件で便へ割当」で選択日の便へ往路と復路を一括割当
7. 例外便は便情報から往路経路と復路経路を個別変更

時間帯と車両番号が空欄の経路は、その路線と方向の基本経路として扱います。時間帯がある経路を優先し、さらに車両番号が一致する経路を最優先します。このため、本川越線では基本、朝、夕方、特定車両などの複数経路を登録できます。

地図表示にはOpenStreetMap標準地図を使います。表示中の範囲だけを読み込み、地図上へ著作権表示を常時表示します。道路経路の計算は初期値としてOSRM公開処理を使います。公開処理には可用性保証がないため、本運用で継続利用する場合は専用OSRMまたは契約済み経路処理へ変更してください。

専用OSRMへ変更する場合は環境変数 `ROUTING_API` に基点URLを指定します。

```bash
ROUTING_API=https://routing.example.jp go run .
```

読込中と保存中には待機表示を出し、処理中の重複操作を防止します。動きの軽減設定にも対応しています。

## 初回ログイン設定

起動前に `APP_USERS` へ職員番号、表示名、権限、暗証番号をJSONで指定します。配布物には初期暗証番号を埋め込んでいません。

権限は次の3種類です。

1. `admin` は元ダイヤ、経路、学校地点、運休、待機への戻しを含む全操作
2. `driver` は当日運行、人数、受付、出発、到着、担当運用設定
3. `viewer` は当日運行、全車両位置、履歴の閲覧だけ

例

```bash
APP_USERS='[{"id":"1001","name":"運行管理者","role":"admin","pin":"変更してください"},{"id":"2001","name":"運転担当","role":"driver","pin":"変更してください"},{"id":"3001","name":"閲覧担当","role":"viewer","pin":"変更してください"}]' go run .
```

暗証番号は4文字以上です。5回連続で失敗した接続元は5分間停止します。ログインは12時間有効で、処理側を再起動すると全員が再ログインします。本番では環境変数を端末履歴へ残さず、OSのサービス設定や秘密情報管理から渡してください。

## 起動

Go 1.22以上を用意し、このフォルダで次を実行します。

```bash
APP_USERS='[{"id":"1001","name":"管理者","role":"admin","pin":"安全な暗証番号"}]' go run .
```

ブラウザで `http://localhost:8080` を開くと一般用の時刻案内が表示されます。ダイヤ管理は `http://localhost:8080/diagram`、職員用は `http://localhost:8080/staff` です。

現在のダイヤは `data/store.json` に投入済みです。別のExcelへ更新する場合は、画面の「ダイヤ取込」からxlsxを選択します。

## 保存先

初期値は `data/store.json` です。変更する場合は環境変数 `DATA_FILE` に絶対パスを指定します。

例

```bash
DATA_FILE=/var/lib/school-bus/store.json go run .
```

実運用では、毎日バックアップされる永続領域を指定してください。

## Docker

```bash
docker build -t school-bus-go .
docker run --rm -p 8080:8080 -e APP_USERS='[{"id":"1001","name":"管理者","role":"admin","pin":"安全な暗証番号"}]' -v "$PWD/data:/app/data" school-bus-go
```

## Renderへの公開

`render.yaml` を同梱しています。Renderのダッシュボードで「New」から「Blueprint」を選び、このリポジトリを指定すると、Dockerfileから構築して公開します。

1. `APP_USERS` はRenderの環境変数へ設定します。値はリポジトリへ置きません
2. 保存先は永続ディスク `/var/lib/school-bus` です。ディスクは有料プランで利用できます
3. 初回起動時だけ、イメージ同梱の `data/store.json` を保存先へ複製します（環境変数 `SEED_FILE`）
4. 監視は `/healthz` を使います

公開後のURLは、一般用が `https://<サービス名>.onrender.com/`、ダイヤ管理が `/diagram`、職員用が `/staff` です。RenderはHTTPSで終端するため、ログイン用のCookieは `X-Forwarded-Proto` を見てSecure属性を付けます。

永続ディスクを付けずに公開すると、再起動のたびに運行実績と変更したダイヤが失われます。必ずディスクを設定してください。

## Google Cloud Runについて

Cloud Runの通常のファイル領域は再起動時に保持されません。そのまま公開すると運行実績が消える可能性があります。Cloud Runで使う場合は、永続保存をCloud StorageやFirestoreへ差し替える必要があります。

現状のJSON保存版は、永続ディスクを持つVPS、校内端末、NAS上のDocker運用に適しています。

## 公開時の注意

この版は職員番号と暗証番号によるログインを備えています。ただし、校外へ公開する場合はHTTPSを必須とし、学校内ネットワーク、VPN、接続元制限なども併用してください。暗証番号は処理側の環境変数からのみ読み込み、画面や保存データには書き込みません。

案内設定 `/guide` はログインなしで開きます。当日その場で直せるようにするためですが、URLを知る人は誰でも一般用の表示内容を書き換えられます。校外へ公開する場合は `GUIDE_LOCK=1` を設定してログインを必須にするか、接続元を制限してください。

```
GUIDE_LOCK=1 go run .
```

来場者の検索は混雑予測のためだけに数えます。保存するのは日付、向き、駅、15分単位に丸めた希望時刻、件数だけです。個人を識別する情報、IPアドレス、Cookieは保存しません。
